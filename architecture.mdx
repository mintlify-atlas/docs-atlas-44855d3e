RutaMovil is built on a three-tier architecture: a **React Native 0.82 mobile client** that runs on both Android and iOS, a **Spring Boot REST API** deployed on Google Cloud Run that owns all business logic and persistence, and a **Firebase** layer that handles identity, push notifications, and the initial token exchange. A persistent **STOMP/SockJS WebSocket** channel sits alongside the REST API to push accident events to authority dashboards without polling. Understanding how these tiers relate to each other is the foundation for working on any part of the codebase.

## Backend REST API

All HTTP communication goes through a single Axios instance configured in `src/services/api.jsx`. The base URL, 15-second timeout, and `Content-Type` header are set once and shared across every API call in the app.

```jsx
// src/services/api.jsx
import axios from "axios";

const api = axios.create({
  baseURL: "https://backend-spring-527951342134.us-central1.run.app/api",
  timeout: 15000,
  headers: {
    "Content-Type": "application/json",
  },
});

export default api;
```

Import this instance wherever you need to call the backend:

```jsx
import API from '../services/api';

// Role lookup during login
const response = await API.post("/login/login", {
  correo: correo.toLowerCase().trim(),
  contrasena: password,
});

// MFA verification
const verifyResponse = await API.post("/mfa/verify-login", {
  email: mfaEmail,
  code: parseInt(mfaCode),
});
```

<Info>
  The backend is stateless. There is no session cookie — role and identity data returned at login time are kept in React component state and passed down as props to dashboards.
</Info>

## Firebase Services

Firebase provides two distinct capabilities in RutaMovil: **identity** (via Firebase Auth) and **push notifications** (via Firebase Cloud Messaging).

### Authentication (`src/services/firebase.jsx`)

The `FirebaseService` class wraps `@react-native-firebase/messaging` and Notifee into a single initialisation lifecycle:

1. **Request permission** — calls `messaging().requestPermission()` on first launch.
2. **Retrieve FCM token** — calls `messaging().getToken()` and stores the result.
3. **Register token** with the backend at `POST /transportistas/fcm-token` or `POST /autoridades/fcm-token`.
4. **Listen for messages** — foreground messages are displayed as local Notifee notifications on the `sicher-accidents` Android channel; background messages are handled by the Firebase background handler.

The `useFirebaseNotifications(userId, userType)` hook encapsulates the full initialization flow and is consumed inside each role dashboard.

### Google Sign-In

Google Sign-In is configured in `Login.jsx` using `@react-native-google-signin/google-signin`:

```jsx
GoogleSignin.configure({
  webClientId:
    "267093356780-61j6l12lhevi4a14q7aihook3bna9i64.apps.googleusercontent.com",
  offlineAccess: true,
  forceCodeForRefreshToken: true,
});
```

The resulting `idToken` is exchanged for a Firebase credential via `GoogleAuthProvider.credential(idToken)`, then passed to `signInWithCredential(auth, googleCredential)`. After Firebase confirms the identity, the app calls `POST /api/login/google-login` to fetch the user's role and check MFA status.

## Real-Time WebSocket Channel

The `WebSocketService` class (`src/services/websocketService.jsx`) maintains a STOMP client over a SockJS transport. It subscribes to `/topic/accidentes` immediately on connect and delivers parsed JSON payloads to a caller-supplied callback:

```jsx
// src/services/websocketService.jsx
import { Client } from '@stomp/stompjs';
import SockJS from 'sockjs-client';

// Inside WebSocketService.connect():
this.client = new Client({
  webSocketFactory: () => new SockJS(url),
  reconnectDelay: this.reconnectDelay,       // 3 000 ms base
  heartbeatIncoming: 10000,
  heartbeatOutgoing: 10000,
  forceBinaryWSFrames: true,
  appendMissingNULLonIncoming: true,

  onConnect: (frame) => {
    const subscription = this.client.subscribe(
      '/topic/accidentes',
      (message) => {
        const data = JSON.parse(message.body);
        if (onMessageCallback) onMessageCallback(data);
      }
    );
    this.subscriptions.push(subscription);
  },
});

this.client.activate();
```

Reconnection uses exponential backoff (`reconnectDelay × 2^(attempt − 1)`) up to five attempts before giving up.

  </Card>
  <Card title="src/services/websocketService.jsx" icon="plug">
    Singleton STOMP/SockJS client. Subscribes to `/topic/accidentes`, delivers live accident events, and manages exponential-backoff reconnection.

```
        │
        ▼
  Login.jsx renders
        │
        ├─── Email / Password ──► POST /api/login/login
        │                                │
        │                    ┌───────────┴────────────┐
        │              requiresMFA: true        requiresMFA: false
        │                    │                         │
        │           MFA code entry screen      Role dashboard renders
        │                    │
        │           POST /api/mfa/verify-login
        │                    │
        │           POST /api/login/complete-mfa
        │                    │
        │              Role dashboard renders
        │
        └─── Google Sign-In ─► Firebase Auth ──► POST /api/login/google-login
                                                         │
                                             (same MFA branch as above)
```

<Note>
  Admin authentication bypasses the standard login flow. The **🔑 Acceso administrador** button at the bottom of the Login screen opens `LoginAdmin`, which has its own credential verification against a separate admin endpoint.
</Note>
